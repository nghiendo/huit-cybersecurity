Các thuật toán sử dụng trong project Web Attack Detection

1. Mục tiêu của project

Project xây dựng pipeline phân loại request hoặc payload web thành 4 lớp:

  • Normal
  • SQLi
  • XSS
  • OtherWebAttack

Notebook chính kết hợp nhiều nhóm thuật toán theo chuỗi: đọc dữ liệu, làm sạch, trích xuất đặc trưng, xử lý mất cân bằng, huấn luyện nhiều mô hình, chọn mô hình tốt nhất bằng validation, rồi đánh giá cuối trên test set.

2. Quy trình tổng thể

  1. Đọc nhiều nguồn dữ liệu web attack
  2. Chuẩn hóa text và cột dữ liệu
  3. Trích xuất đặc trưng số từ payload HTTP
  4. Loại conflict label và loại bản ghi trùng
  5. Chia train / validation / test
  6. Balance train bằng oversampling
  7. Train 6 mô hình
  8. Chọn best model bằng validation
  9. Train lại trên train + validation
  10. Đánh giá cuối trên test

3. Thuật toán đọc và chuẩn hóa dữ liệu

3.1. Đọc dữ liệu từ nhiều nguồn

Project dùng hai hàm chính:

  • load_csic_dataset(...)
  • load_payload_dataset(...)

Các nguồn hiện có:

  • CSIC 2010
  • SQLi Extended
  • SQLi
  • SQLi V2
  • SQLi V3
  • XSS dataset

Mục tiêu của bước này là quy toàn bộ dữ liệu về một schema thống nhất gồm source, raw_text, label_binary, label_multiclass và nhóm numeric features.

3.2. Làm sạch text bằng normalize_text

Hàm normalize_text(...) thực hiện:

  1. ép giá trị về string
  2. thay null byte \x00
  3. loại control characters
  4. thay newline, tab bằng khoảng trắng
  5. gộp nhiều khoảng trắng liên tiếp
  6. trim đầu cuối
  7. đưa về chữ thường

Kết quả là text đầu vào ổn định hơn cho TF-IDF, deep model và bước dedup.

3.3. Đọc CSV robust

Hàm read_csv_robust(...) thử nhiều cấu hình đọc file:

  • encoding: utf-8-sig, utf-16, utf-16-le, utf-16-be, latin1
  • separator: , hoặc \t

Sau đó project làm sạch header bằng:

  • clean_column_name(...)
  • make_unique(...)
  • clean_dataframe(...)

Điểm mạnh của thuật toán này là chịu lỗi tốt với các file dữ liệu gốc không đồng nhất về encoding và header.

3.4. Quy đổi nhãn về 4 lớp

Project dùng parse_binary_label(...) để nhận diện dòng dữ liệu là normal hay attack, rồi ánh xạ sang multiclass:

  • Normal nếu benign hoặc normal
  • SQLi nếu đến từ các nguồn SQL injection
  • XSS nếu đến từ nguồn XSS
  • OtherWebAttack nếu là attack từ CSIC

4. Thuật toán trích xuất đặc trưng số

Hàm trung tâm là extract_http_features(...).

Project tạo các đặc trưng như:

Độ dài và tỷ lệ
  • text_length
  • raw_length
  • length_delta
  • special_char_ratio
  • digit_ratio
  • letter_ratio
Dấu ký hiệu nghi vấn
  • số dấu ?, &, =
  • quote, semicolon, dash
  • angle brackets
  • parenthesis
  • slash, percent
Tín hiệu an ninh web
  • encoding markers
  • HTTP method
  • SQL keywords
  • script keywords
  • command keywords
  • traversal patterns

Step-by-step

  1. nhận chuỗi đầu vào
  2. chuẩn hóa bằng normalize_text(...)
  3. đếm dấu hiệu cú pháp và từ khóa
  4. tính ratio cho một số thuộc tính
  5. trả về dictionary numeric feature

5. Thuật toán chống duplicate và leakage

5.1. Tạo hash

Project dùng sha256_text(...) để tạo text_hash từ normalized_text.

5.2. Loại conflict label

  1. group theo text_hash
  2. tìm những hash có nhiều hơn một label_multiclass
  3. loại toàn bộ các bản ghi conflict

5.3. Deduplicate

  1. sau khi bỏ conflict, project gọi drop_duplicates theo text_hash
  2. giữ lại một bản ghi đầu tiên

Mục tiêu là tránh cùng một payload đi vào nhiều split hoặc tạo nhãn mâu thuẫn cho mô hình.

6. Thuật toán chia dữ liệu

Project dùng train_test_split(...) với stratification theo label_multiclass.

  1. chia data thành train_df và temp_df với test_size=0.30
  2. chia tiếp temp_df thành val_df và test_df với test_size=0.50
  3. kiểm tra overlap hash giữa train, validation và test
  4. assert rằng số lượng overlap bằng 0

Tỷ lệ cuối cùng là:

  • Train: 70%
  • Validation: 15%
  • Test: 15%

7. Thuật toán xử lý mất cân bằng lớp

Project dùng random oversampling trong make_balanced_training_frame(...).

Step-by-step

  1. đếm số lượng mẫu mỗi lớp
  2. chọn kích thước lớp lớn nhất làm target_size
  3. duyệt từng lớp
  4. nếu lớp nhỏ hơn target thì lấy mẫu lặp lại bằng resample(..., replace=True)
  5. nối tất cả nhóm lại
  6. shuffle toàn bộ train đã balance

Validation và test không được oversample để giữ đánh giá khách quan.

8. Các mô hình học máy sử dụng trong project

Mô hình Input Nhóm thuật toán
TF-IDF + Logistic Regression Text Classical NLP
TF-IDF + Linear SVC Text Classical NLP
Random Forest trên statistical features Numeric Tree-based ML
Multi-view TF-IDF + stats + Logistic Regression Text + Numeric Hybrid classical
CNN + BiLSTM Text Deep learning
Multi-view CNN-BiLSTM + stats branch Text + Numeric Hybrid deep learning

9. Mô hình 1: TF-IDF + Logistic Regression

Tên model: logistic_regression_tfidf

Thành phần:

  • TfidfVectorizer(analyzer='char_wb', ngram_range=(3, 5), min_df=2, max_features=100000)
  • LogisticRegression(max_iter=1000, class_weight='balanced')

Step-by-step

  1. lấy cột normalized_text
  2. biểu diễn text bằng TF-IDF trên character n-gram 3 đến 5
  3. tạo ma trận đặc trưng sparse
  4. Logistic Regression học trọng số cho từng lớp
  5. chọn lớp có điểm cao nhất để dự đoán

Character n-gram giúp bắt tốt các pattern như ' or 1=1, <script>, chuỗi encode và ký hiệu bất thường.

10. Mô hình 2: TF-IDF + Linear SVC

Tên model: linear_svm_tfidf

Thành phần:

  • TfidfVectorizer(analyzer='char_wb', ngram_range=(3, 5), min_df=2, max_features=120000)
  • LinearSVC(class_weight='balanced')

Step-by-step

  1. vector hóa text bằng TF-IDF
  2. xây dựng siêu phẳng tuyến tính phân tách các lớp
  3. so sánh decision score để chọn nhãn

Linear SVC phù hợp với không gian đặc trưng lớn và thưa, rất phổ biến trong text classification.

11. Mô hình 3: Statistical Features + Random Forest

Tên model: statistical_features_random_forest

Thành phần:

  • StandardScaler()
  • RandomForestClassifier(n_estimators=300, class_weight='balanced_subsample', n_jobs=-1)

Step-by-step

  1. lấy toàn bộ NUMERIC_FEATURE_COLS
  2. điền giá trị thiếu bằng 0
  3. scale dữ liệu số
  4. huấn luyện nhiều cây quyết định
  5. gộp kết quả bỏ phiếu để ra nhãn cuối

Mô hình này đặc biệt tận dụng các heuristic security signals thay vì đọc text trực tiếp.

12. Mô hình 4: Multi-view TF-IDF + Stats + Logistic Regression

Tên model: multiview_tfidf_stats_logistic_regression

Thành phần:

  • ColumnTransformer
  • nhánh text: TfidfVectorizer(...)
  • nhánh numeric: StandardScaler()
  • LogisticRegression(...)

Step-by-step

  1. chuẩn bị input gồm text và numeric features
  2. xử lý text và numeric theo hai nhánh riêng
  3. ghép hai loại đặc trưng bằng ColumnTransformer
  4. huấn luyện Logistic Regression trên vector hợp nhất

Đây là mô hình hybrid classical kết hợp nội dung payload và đặc trưng cấu trúc.

13. Mô hình 5: CNN + BiLSTM cho text

Tên model: cnn_bilstm_text

Kiến trúc:

  1. TextVectorization
  2. Embedding(50000, 64)
  3. Conv1D(96, kernel_size=5, relu)
  4. MaxPooling1D(2)
  5. Bidirectional(LSTM(64))
  6. Dropout(0.35)
  7. Dense(64, relu)
  8. Dropout(0.25)
  9. Dense(num_classes, softmax)

Step-by-step

  1. mã hóa nhãn bằng LabelEncoder
  2. học vocabulary bằng TextVectorization.adapt(...)
  3. chuyển text thành chuỗi token id có chiều dài cố định
  4. dùng embedding để học vector dense
  5. dùng Conv1D để học local patterns
  6. dùng BiLSTM để học ngữ cảnh theo thứ tự
  7. softmax tạo xác suất cho 4 lớp
  8. huấn luyện bằng Adam và dừng sớm theo val_loss

14. Mô hình 6: Multi-view CNN-BiLSTM + Stats Branch

Tên model: multiview_cnn_bilstm_text_stats

Nhánh text: TextVectorization → Embedding → Conv1D → MaxPooling1D → BiLSTM → Dropout

Nhánh numeric: StandardScaler → Dense(64) → Dropout → Dense(32)

Hợp nhất: Concatenate → Dense(96) → Dropout → Softmax

Step-by-step

  1. encode nhãn bằng LabelEncoder
  2. scale numeric features
  3. vectorize text
  4. text branch học đặc trưng tuần tự từ payload
  5. numeric branch học từ heuristic features
  6. nối hai vector biểu diễn
  7. dense layers học tương tác giữa hai view
  8. softmax xuất ra phân loại cuối

Đây là mô hình tổng hợp mạnh nhất về mặt ý tưởng vì nó kết hợp text raw và tín hiệu thống kê.

15. Thuật toán đánh giá mô hình

Project dùng hai helper:

  • evaluate_frame(...) cho classical model
  • evaluate_deep_predictions(...) cho deep model

Các chỉ số chính:

  • Accuracy
  • F1 macro
  • F1 weighted

F1 macro là chỉ số quan trọng nhất vì bài toán có mất cân bằng lớp.

16. Thuật toán chọn best model

Sau khi train toàn bộ mô hình, project tạo validation_table và sắp xếp theo:

  1. f1_macro giảm dần
  2. nếu bằng nhau thì accuracy giảm dần

Mô hình đứng đầu được gán cho best_model_name.

17. Thuật toán final training trước khi test

  1. gộp train_df và val_df thành trainval_df
  2. rebalance lại thành trainval_balanced_df
  3. lấy best_model_name
  4. train lại mô hình tốt nhất trên train + validation
  5. dự đoán trên test_df
  6. in classification_report và vẽ confusion_matrix

18. Kết luận

Project này là một pipeline nhiều tầng, không phải chỉ một mô hình đơn lẻ. Ba ý tưởng cốt lõi nhất là:

  • biểu diễn text bằng character-level TF-IDF hoặc deep sequence model
  • trích xuất handcrafted HTTP/security features
  • multi-view learning kết hợp text và numeric signals

Tóm lại, hệ thống kết hợp cả tri thức thủ công về security pattern lẫn khả năng học tự động của machine learning và deep learning để phân loại payload web attack.
